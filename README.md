# Mini-PDM

Локальное настольное PDM-приложение для импорта CAD-документов, ведения версий изделий и сборок, просмотра состава, расчёта массы и формирования спецификации.

## Быстрый запуск в Docker

Для Windows и macOS установите Docker Desktop с Docker Compose. Для Linux нужны Docker Engine и Docker Compose. Из терминала выполните:

```sh
git clone https://github.com/aksis7/mdm.git
cd mdm
docker compose up -d --build
```

При первом запуске Docker соберёт приложение, запустит PostgreSQL, применит миграции и поднимет Avalonia Desktop в браузере. Откройте <http://localhost:8080>.

## Нативное окно

Вместо браузерного режима приложение можно запустить отдельным окном. Используйте скрипт для своей системы.

**Windows, PowerShell:**

```powershell
.\start.cmd
```

**Linux:**

```sh
./start.sh
```

**macOS:**

```sh
./start.command
```

## Возможности

- Импорт `.a3d` и `.m3d` файлов из выбранной папки. Данные документов — JSON в UTF-8.
- Просмотр PDM-объектов, поиск и работа с версиями.
- Управление состояниями версий: «В работе», «Утверждено», «Аннулировано».
- Просмотр состава сборки, расчёт массы и сводной спецификации.
- Проверка ссылок на компоненты, количеств и циклов в составе.
- Отчёт импорта с результатом и причиной по каждому файлу.
- Фоновая очистка временных файлов импорта.

## Архитектура и данные

Desktop-клиент на Avalonia общается по HTTP с ASP.NET Core API. API использует модули с CQRS/MediatR; общие бизнес-правила находятся в Domain, доступ к данным реализован через EF Core и PostgreSQL.

В базе хранятся объекты PDM, их версии и состав сборок. Строки состава связывают версию сборки с дочерним объектом и количеством. Расчёт использует текущую неаннулированную версию дочернего объекта. Миграции EF Core применяются при запуске Docker Compose.

База PostgreSQL и сохранённые исходные CAD-файлы находятся в Docker volumes и сохраняются после `docker compose down`.

## Принятые решения

- Для доступа к PostgreSQL выбран EF Core.
- Изменяемые атрибуты детали или сборки хранятся в версии, чтобы утверждённые версии сохраняли историю.
- Идентифицирующее имя стандартного изделия хранится у объекта; масса — в версии.
- Состав ссылается на дочерний объект, а расчёты используют его текущую версию.

Приложение сейчас рассчитано на локальную работу администратора и не включает аутентификацию.

## Сборка и тесты

Для сборки и запуска тестов из исходников требуется .NET SDK 10:

```sh
dotnet restore MiniPdm.sln
dotnet build MiniPdm.sln
dotnet test MiniPdm.sln
```

PostgreSQL-интеграционные тесты запускаются отдельно и требуют настроенной тестовой базы через `PDM_TEST_POSTGRES_CONNECTION`.

## Проверка на тестовых наборах

Первый набор `cad-export` содержит 45 файлов: 35 приняты, 10 отклонены; среди принятых есть один документ с предупреждением об отсутствующей массе.

Затем импортируется `cad-export-v2`. В нём масса «Колеса зубчатого» меняется с 5,86 до 5,92 кг, а количество прокладок в «Крышке подшипника» — с 3 до 4. Для этих изменений создаются новые версии; остальные неизменившиеся документы не должны получать новые версии.
